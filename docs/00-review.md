# Deusmith-MemorySystem 设计评审（00）

对《智能体"类人脑"记忆架构计划》（Deusmith-Memory.txt）的逐条评审。
判定四档：**保留 / 修改 / 删除 / 补充**。每条附失效机制（它在生产上怎么坏），不只说"不合理"。

## 已锁定的前提（与需求方确认，不再重议）

| 前提 | 值 |
|---|---|
| 部署形态 | 本地单机智能体；持久层只有 **PostgreSQL + pgvector**（明确不用 SQLite） |
| 主场景 | 长期个人助理：偏好/事实/事件跨会话记忆，情绪与个性化重要 |
| 写入侧 | embedding 必需（本地模型或 API 二选一，运行时可配）；LLM 挂钩可选，**规则引擎保底**，任何 LLM 不可用时全链路可跑 |
| 身份人格 | 属于深层记忆节点（原计划已明确，不重复讨论） |

**红线声明**：生物隐喻（Ebbinghaus/Act-R）只提供曲线形状与变量选择，**参数最终由评估指标决定**，不追求"更像大脑"。这条不写进文档开头，后续评审会一路跑偏。

## 判定表

### §1 总体目标与设计原则

| 条目 | 判定 | 失效机制 / 理由 |
|---|---|---|
| 分层存储（浅/中/深） | **保留** | 与人类记忆粗粒度同构，且映射到不同的存储引擎，是全文档最有价值的一条 |
| 双路检索（向量+图游走+加权） | **保留** | 纯向量检索对"关联但不相似"的记忆失明（例：查"会议偏好"召不回"上周定了周二晨会"这条事件） |
| 写读分离（在线轻写/离线治理） | **保留** | 在线做压缩会把写入延迟拖到秒级 |
| 证据优先（可信度四因子） | **保留** | 无可信度的记忆库会被单次幻觉污染且无法自愈 |
| 预算约束（Token/延迟/隐私） | **保留** | 无预算的召回会把上下文窗口挤爆，反而降低回答质量 |
| 可替换组件 | **保留** | 与"框架是加速器"原则一致 |

### §2 记忆分层与流转规则

| 条目 | 判定 | 失效机制 / 理由 |
|---|---|---|
| 浅层=上下文窗口+KV缓存+滚动摘要 | **修改** | 本地单机形态下 Redis 是第 2 个常驻服务，运维成本 > 收益。改为：**进程内会话存储（默认）+ Redis 适配器接口（可选）**。失效机制：为了 0.3ms→0.05ms 的延迟提升多养一个服务，单用户场景纯亏 |
| 浅层≤窗口30%、N=10轮、30分钟清理 | **保留** | 数值合理，作为可调参数固化 |
| 中层容量"20万节点/每类1万" | **修改** | 无评估集之前的容量触发式归档会误删。改为：**TTL/权重触发归档（保留），容量指标只做监控告警不做动作** |
| 中层90天滑动TTL | **修改** | TTL 与连续衰减函数并存会打架（见 §四评审）。TTL 重定义为**导出量**：`t_archive = -τ_eff · ln(θ_archive)`，θ_archive=0.2 为归档分数阈值，90 天改为监控参考值而非独立常数 |
| 深层无TTL、版本链、只可废止 | **保留** | 身份/价值观被静默覆盖是助理场景最严重事故，版本链是唯一合规做法 |
| 浅→中（重复≥2 / importance≥0.7 / 显式记住） | **保留** | 阈值可作为 tunable，结构正确 |
| 中→深（conf≥0.9、auth≥0.8、跨会话≥5、人工确认） | **保留** | 人工确认为硬门，代码层强制 identity_policy 类必须 human_confirmed |
| 中层降级/归档四条件 | **保留** | 但"90天未访问且weight<0.2"的判定改用上面的导出公式，避免双轨制 |

### §3 节点与链路模型

| 条目 | 判定 | 失效机制 / 理由 |
|---|---|---|
| 九种节点类型 + 通用字段集 | **保留** | 字段基本齐，单表+类型判别正确（图游走需要同构 ID 空间） |
| 节点字段缺**槽位** | **补充** | **这是原计划最贵的一个缺口**（详见错误#1）。冲突判定需要 (subject, predicate, object, polarity) 四槽位，只有 content+vector 无法可靠判冲突：`cos("我喜欢摄影", "我不喜欢摄影了") ≈ 0.95`，语义相似度把"否定"当"重复"。补四个字段进 schema |
| 九种边类型 + 方向约定 | **保留** | 方向约定清晰（时序早→晚、因果因→果、支持证据→结论、冲突无向、摘要摘要→被摘要） |
| 即时建边 topK=20 | **保留** | 每次写入 20 次 ANN 查询在 pgvector HNSW 下是亚毫秒级 |
| 边合并 w=1-(1-w)(1-Δ) | **保留** | 饱和强化保证幂等且不上溢 |
| 环路用 SCC 检测 | **保留** | Tarjan 纯 Python 实现即可，E 的线性复杂度 |
| 剪枝（w<0.1 ∧ 60天 ∧ conf<0.3） | **保留** | 三条件与门避免误删 |

### §4 参数体系与耦合

| 条目 | 判定 | 失效机制 / 理由 |
|---|---|---|
| 参数耦合关系六条 | **保留** | 方向全部正确，落成不变量 I6（单调性）+ 单测 |
| decay_rate/ttl 作为节点字段 | **修改** | 能被 S 导出的量不是参数。decay_rate=τ_base 的倒数缩放，存表只会产生双写不一致。改为：**参数区唯一权威，节点表不存 decay_rate**；ttl 字段仅存"归档期限覆盖值"（可空） |
| 超参表数值 | **保留（含错误修正）** | 见错误#2：文档自己的数值演算漏乘了一个因子。参数默认值照抄，但**数值必须由代码复算并有单测钉死** |
| tunable 参数约 30 个 | **修改** | 收敛为 7 个独立可调维度：τ_base、打分指数组(α,β,γ,δ,ε)、强化组(η,η_e,λ_e)、MMR λ、召回组(topK,hops,budget)、晋升阈值组、聚类阈值。其余为结构常数。理由：探针集 <300 条时，30 个自由参数必然过拟合到自造测试上 |

### §5 核心算法

| 条目 | 判定 | 失效机制 / 理由 |
|---|---|---|
| decay_recency 指数衰减公式 | **保留** | O(1) 在线计算正确；Act-R 幂律校准**移到演进**（无评估数据时校准是空转） |
| reinforce（η=0.3 饱和式） | **保留** | w+η(1-w)·s 有上界，配合在线 recency 不会数值爆炸 |
| tier_transition | **保留** | 补一条：晋升深层时 identity_policy 类**硬性要求 human_confirmed**，代码不接受绕过 |
| update_edges | **保留** | 冲突边保留并降权——正确，冲突是信息不是噪音 |
| estimate_confidence sigmoid 五因子 | **保留** | 权重和=1.2 不必归一（非 softmax），但**单调性要有单测** |
| 检索打分 score 公式 | **修改** | rel_norm 用 min-max/rank **按当次查询归一是错的**：任何查询的头名恒为 1.0，绝对阈值（如"score<0.45 视为没记住"）将一次也不会触发，阈值不可跨查询移植。改为：**多路 RRF 融合 + 绝对参考点归一**（参考点=所有通道都排第一的融合值），保留绝对下限+相对截断双闸 |
| MMR λ=0.7 | **保留** | 防同主题挤占预算，λ 作为 tunable |
| compress_merge（cos≥0.9 聚类） | **修改** | 两处：①摘要节点本身必须豁免再聚类，否则级联压缩滚雪球——补 `generation` 深度上限；②聚类阈值按 type 分档（事件 0.85 / 事实 0.92）留接口，默认统一 0.9 |
| 冲突仲裁"高权威+新证据优先" | **保留** | 补红线 enforcement：深层不允许静默覆盖——schema 层触发器拦截，不只靠应用层自觉 |
| 写/读/离线三条调用顺序 | **保留** | 与实现一一对应 |

## 三个最贵的错误（量化）

### 错误#1：冲突/去重按语义相似度判定 —— 数据损毁级

原计划只有 content + content_vector，去重靠内容 hash、冲突靠"高权威新证据"。但**改写问法**（"我不再喜欢摄影了"）与原记忆（"我喜欢摄影"）的余弦相似度 ≈0.95，hash 不同、相似度极高：
- 若按 cos≥0.9 去重 → 改写被当重复丢弃，**用户的偏好更新永久丢失**；
- 若按相似度触发覆盖 → 一条极性相反的记忆**静默顶掉**正确记忆。

修复：槽位身份 `(scope, subject, predicate)` 匹配 + 极性/宾语比对判冲突；冲突进 contested 状态走仲裁，绝不静默覆盖（不变量 I3）。
量化（scripts/eval_probes.py 实测，见 docs/eval-report.md）：**否定对相似度 mean=0.655（0.557–0.738）高于良性改写对 mean=0.504（0.323–0.760），两类区间重叠——θ=0.5/0.6 时否定更新丢失 5–6/8；θ≥0.8 时良性改写合并 0/8（判据失效）。不存在能同时『合并良性改写』与『零丢失否定更新』的相似度阈值。槽位+极性判定：否定更新保留 8/8，且多值谓语（喜欢）换宾语不误判为冲突（开发中实际修掉的 bug）。**

### 错误#2：公式链里一个漏乘因子 —— 校准级

文档 §9.3 自带的演算：`score ≈ 0.8^1 · 0.6^0.8 · 0.71^0.6 · 0.9^1 · 0.8^0.5 ≈ 0.39`。实际连乘 = **0.3489**（0.39 恰好是漏乘 importance^ε=0.8^0.5 的积：0.3901）。相对误差 **+11.8%**。
失效机制：若"score<0.45 视为没记住"这类绝对阈值按 0.39 校准，真实分布整体偏低 12%，**该触发的一次也不会触发**——你在批评别人"阈值不可移植"的同时，自家的阈值已经失效。
修复：所有文档数字由 `demo --demo` 从代码产出；单测钉死 m102 的 S、recency、score 三个值（±0.001）；`scripts/check_params.py` 保证参数表↔代码默认值一致。

### 错误#3：单机起步栈过重 —— 成本级

原计划默认栈 = Redis + PG/pgvector + Neo4j/FalkorDB + PG版本表 + MinIO + （可选 Mem0）。单用户本地形态：≥4 个常驻服务、约 2GB 内存基线、4 个故障域、4 套备份。
修复：v1 = **PG+pgvector 单库**（节点/边/日志/版本/审计同库）+ 进程内浅层 + 本地证据目录；Redis/Neo4j/MinIO/Qdrant 全部留适配器接口，按原计划 §8.5 的触发条件演进。**接口先行，服务后置。**
实测（scripts/bench_pg.py，PG17.6+pgvector 0.8.7，2 万节点/20 万边/HNSW 256 维）：
- HNSW 向量 top-50 召回：**p50=2.2ms**；
- 图游走 2 跳（有界 100/跳，生产路径）：**p50=10.4ms**；五通道全量检索 **p50=18.5ms**——单库满足单用户延迟预算；
- 两个附带发现：①递归 CTE 全表扫描在 2 万边时即 150–340ms，已改为逐跳索引 BFS；②**图游走必须有界**——无界 2 跳在度 20 的稠密图上物化上万条子图边，实测 214ms，有界后 10ms。

## 如果只做三件事

1. **槽位+极性冲突判定与 supersedes 链**（错误#1）——先保证不毁数据，再谈智能。
2. **绝对刻度打分 + 参数↔代码一致性校验**（错误#2）——`check_params.py` 进每次提交，数值进单测。
3. **探针门禁 `eval_probes.py`**——七类探针 ≥50 节点场景，每次调参有对照；门禁不过不许合入。

## 补充项 → 不变量/表约束映射（评审落不了地的补充等于建议）
