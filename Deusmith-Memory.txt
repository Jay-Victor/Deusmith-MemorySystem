智能体“类人脑”记忆架构计划
│
├─ 一、总体目标与设计原则
│  ├─ 1、总体目标
│  │  ├─ 可工程落地：时间衰减、交互强化、关联检索、层级流转、冲突仲裁、上下文注入
│  │  └─ 与上下文窗口衔接：窗口只承载工作记忆投影；持久记忆按需召回、裁剪、摘要后注入
│  └─ 2、设计原则
│     ├─ 分层存储：浅层工作记忆 / 中层情景语义记忆 / 深层核心知识与策略记忆
│     ├─ 双路检索：向量语义召回 + 图关联游走 + 时间/可信度/重要性加权
│     ├─ 写读分离：在线轻量写入；离线负责压缩、合并、剪枝、晋升、降级
│     ├─ 证据优先：可信度由来源权威、证据数量、一致性、新鲜度共同决定
│     ├─ 预算约束：召回、排序、注入受Token、延迟、隐私策略约束
│     └─ 可替换组件：向量库、图库、记忆框架均为可替换组件
│
├─ 二、记忆分层与流转规则
│  ├─ 1、浅层记忆
│  │  ├─ 定位：当前会话工作记忆（最近对话原文、工具结果、临时实体、任务状态）
│  │  ├─ 存储：上下文窗口 + Redis/KV会话缓存 + 滚动摘要对象
│  │  ├─ 容量：浅层≤上下文窗口30%；最近N轮原文默认N=10；超出滚动摘要
│  │  ├─ TTL：会话结束后30分钟清理原文；滚动摘要保留至会话结束并进入中层候选
│  │  └─ 触发：每轮写入；每轮或若干轮滚动摘要；会话结束触发中层晋升评估
│  ├─ 2、中层记忆
│  │  ├─ 定位：跨会话用户偏好、事实、事件摘要、任务经验、关系网络
│  │  ├─ 存储：向量库 + 图库/图索引 + 关系库元数据 + 对象存储原文/证据
│  │  ├─ 容量：每用户建议20万节点、每类1万；低权重复节点归档
│  │  ├─ TTL：默认90天滑动TTL；访问/引用/强化则续期；低权重长期未访问转归档
│  │  └─ 触发：会话结束、事件完成、显式“记住”、偏好抽取、定时压缩、检索命中强化
│  ├─ 3、深层记忆
│  │  ├─ 定位：身份设定、核心知识、价值观、安全策略、稳定画像、关键程序性知识
│  │  ├─ 存储：关系库版本表 + 对象存储证据包 + 图库只读核心子图
│  │  ├─ 容量：核心节点建议1万级；版本保留可配置；变更记录不可物理删除，只可废止
│  │  ├─ TTL：无自动TTL；采用版本有效期、审计状态、废止标记管理
│  │  └─ 触发：高置信写入、人工确认、策略发布、冲突仲裁、定期一致性校验
│  └─ 4、层间晋升与降级
│     ├─ 浅→中：显式记住；跨会话重复≥2；importance≥0.7；事件完成形成稳定摘要；偏好被确认
│     ├─ 中→深：跨≥5会话稳定出现；confidence≥0.9；source_auth≥0.8；与既有深层一致；身份/核心偏好/安全策略需人工确认
│     ├─ 中层降级/归档：90天未访问且weight<0.2且无强证据链；被新版本替代；冲突未决且低影响
│     └─ 深层降级/废止：高置信冲突证据；来源失效；策略过期；人工审核废止；保留版本与审计
│
├─ 三、节点与链路模型
│  ├─ 1、节点类型与字段
│  │  ├─ 类型：事件、事实、偏好、情绪、摘要、任务、工具结果、身份/策略、冲突
│  │  ├─ 通用字段：id、type、content、content_vector、embedding_model、created_at、updated_at
│  │  ├─ 时间字段：valid_from、valid_to、last_access_at
│  │  ├─ 来源与可信：source、source_auth、confidence、evidence_refs、consistency
│  │  ├─ 权重与衰减：weight、decay_rate、ttl、activation_count、importance、emotion
│  │  ├─ 治理字段：sensitivity、scope、status、version、supersedes、contested_by、hash、metadata
│  │  └─ 状态：active、archived、contested、deprecated、deleted_logical
│  ├─ 2、链路类型与边权
│  │  ├─ 类型：semantic_similar、temporal_next、causal、co_occur、coref、supports、contradicts、derives_from、summary_of
│  │  ├─ 边字段：edge_id、src_id、dst_id、type、direction、weight、confidence
│  │  ├─ 时间与衰减：created_at、last_reinforced_at、decay_rate
│  │  ├─ 证据与状态：evidence_refs、status
│  │  └─ 方向：时序由早到晚；因果由因到果；支持由证据到结论；冲突双向/无向；摘要由摘要到被摘要节点
│  └─ 3、建边时机与维护
│     ├─ 写入即时建边：kNN候选、规则时序边、指代边、显式因果/支持边，默认topK=20
│     ├─ 离线批量建边：补全语义相似、共现、因果推断、跨会话关联，默认每日或每6小时
│     ├─ 边合并：同源同目标同类型合并；饱和强化 w=1-(1-w)(1-Δ)
│     └─ 剪枝：weight<0.1且60天未强化且confidence<0.3进入候选删除；环路用强连通分量检测、保留最短/最强路径或摘要消解
│
├─ 四、参数体系与耦合关系
│  ├─ 1、核心参数
│  │  ├─ confidence、weight、decay_rate、ttl
│  │  ├─ activation_count、last_access_at、recency
│  │  ├─ emotion、importance、source_auth、sensitivity、consistency
│  │  └─ conflict_penalty、tier_boost、sensitivity_gate
│  ├─ 2、参数耦合
│  │  ├─ activation_count↑ → weight↑ → retrieval_score↑
│  │  ├─ last_access_at越近 → recency↑ → retrieval_score↑
│  │  ├─ importance↑ / emotion↑ / confidence↑ → decay_eff↓ → 有效TTL↑
│  │  ├─ source_auth↑ + consistency↑ + evidence数量↑ → confidence↑ → weight↑
│  │  ├─ conflict_penalty↑ → confidence↓，节点标记contested
│  │  └─ sensitivity↑ → 注入权限和脱敏约束↑，检索候选可能被过滤
│  └─ 3、默认超参表
│     ├─ 衰减：τ_base=7天；importance系数0.8；emotion系数0.5；confidence系数0.7；activation系数0.3
│     ├─ 强化：η=0.3；边强化η_e=0.2；边衰减λ_e=0.01/天
│     ├─ 浅层：N=10；上下文预算占比≤30%；会话结束清理延迟30分钟
│     ├─ 中层：滑动TTL=90天；浅→中阈值重复≥2或importance≥0.7
│     ├─ 深层：中→深confidence≥0.9、source_auth≥0.8、跨会话≥5；变更需审计
│     ├─ 检索：topK=50；图游走2跳；PPR阻尼0.85；MMR λ=0.7；召回Token预算默认4000
│     └─ 打分指数：α=1.0、β=0.8、γ=0.6、δ=1.0、ε=0.5
│
├─ 五、核心算法与函数
│  ├─ 1、遗忘衰减函数
│  │  ├─ 签名：decay_recency(memory, now) -> float
│  │  ├─ 公式：recency = exp(-Δt / (τ_base * S))
│  │  ├─ S = 1 + 0.8*importance + 0.5*emotion_norm + 0.7*confidence + 0.3*ln(1+activation_count)
│  │  ├─ 说明：Ebbinghaus指数衰减做在线时效分；Act-R幂律可用于离线校准
│  │  └─ 默认：τ_base=7天；复杂度O(1)
│  ├─ 2、激活与强化函数
│  │  ├─ 签名：reinforce(memory, signal_strength, now) -> memory
│  │  ├─ 逻辑：activation_count+=1；last_access_at=now
│  │  ├─ 权重：weight=clip(weight+η*(1-weight)*signal_strength,0,1)
│  │  └─ 附带：confidence按证据更新；触发TTL续期；η=0.3；复杂度O(1)
│  ├─ 3、层级流转函数
│  │  ├─ 签名：tier_transition(memory, stats) -> action
│  │  ├─ 输入：跨会话计数、显式记住标记、importance、confidence、source_auth、冲突状态、人工确认
│  │  ├─ 输出：promote_to_middle、promote_to_deep、archive、deprecate、keep
│  │  └─ 默认：浅→中重复≥2或importance≥0.7；中→深confidence≥0.9且source_auth≥0.8且跨会话≥5；复杂度O(1)
│  ├─ 4、链路更新函数
│  │  ├─ 签名：update_edges(node, candidates, now) -> edges
│  │  ├─ 逻辑：共现/引用强化边权；长期无引用按λ_e衰减
│  │  ├─ 冲突与环路：冲突边保留并降权；环路检测后合并或摘要消解
│  │  └─ 默认：边权clip[0,1]；剪枝阈值0.1；即时建边O(K*D)；离线全量O(E log E)
│  ├─ 5、可信度评估函数
│  │  ├─ 签名：estimate_confidence(node, evidence_set) -> float
│  │  ├─ 公式：c = sigmoid(w1*source_auth + w2*consistency + w3*evidence_norm + w4*freshness - w5*conflict_penalty)
│  │  ├─ 冲突仲裁：高权威+高一致+新证据优先；差距小保留双版本status=contested并请求确认
│  │  ├─ 红线：不允许静默覆盖深层记忆
│  │  └─ 默认：w1=0.35、w2=0.25、w3=0.2、w4=0.1、w5=0.3；复杂度O(E)
│  ├─ 6、检索打分函数
│  │  ├─ 签名：retrieval_score(query, memory, now) -> float
│  │  ├─ 公式：score = rel_norm^α * weight^β * recency^γ * confidence^δ * importance^ε * tier_boost * sensitivity_gate
│  │  ├─ 归一化：rel_norm用min-max或rank归一；各项clip到[0.01,1]防零
│  │  ├─ 多样性：score_mmr=λ*score-(1-λ)*max_sim_to_selected
│  │  ├─ 防过拟合：固定超参基线、A/B评估、日志回放、confidence校准、限制单来源占比
│  │  └─ 默认：α=1.0、β=0.8、γ=0.6、δ=1.0、ε=0.5、MMR λ=0.7；复杂度O(N log N + N*K)
│  ├─ 7、记忆压缩与合并函数
│  │  ├─ 签名：compress_merge(nodes, scope) -> summaries
│  │  ├─ 逻辑：按type+scope+cosine≥0.9聚类；生成摘要；合并证据链
│  │  ├─ 图操作：建立summary_of和supersedes边；保留原文引用ID
│  │  └─ 默认：聚类阈值0.9；摘要最大Token可配置；复杂度O(N log N + N*K)
│  └─ 8、调用顺序
│     ├─ 写入路径：解析抽取 → 可信度评估 → 节点落库 → 即时建边 → 触发强化/晋升评估 → 记录日志
│     ├─ 读取路径：查询解析 → 多路召回 → 图游走扩展 → 融合去重 → 检索打分 → MMR裁剪 → 上下文注入
│     └─ 离线路径：衰减重算 → 压缩合并 → 层级流转 → 边剪枝/环路消解 → 一致性校验 → 归档与审计
│
├─ 六、检索与上下文注入
│  ├─ 1、召回阶段
│  │  ├─ 向量检索：按query embedding召回topK，默认K=50
│  │  ├─ 图游走：种子节点2跳邻居扩展或Personalized PageRank，阻尼0.85
│  │  └─ 预过滤：候选先按recency、confidence、importance加权/过滤
│  ├─ 2、排序与筛选
│  │  ├─ 多路融合：向量、图、关键词、最近访问、显式引用合并
│  │  ├─ 去重：按内容hash、摘要归属、supersedes链去重
│  │  ├─ 多样性惩罚：MMR避免同一主题挤占预算
│  │  └─ 预算裁剪：按Token预算、延迟预算、敏感级过滤后截断
│  ├─ 3、注入策略
│  │  ├─ system段：深层身份设定、安全策略、稳定核心偏好、全局约束摘要
│  │  ├─ user段：与当前问题相关的用户事实、偏好、事件摘要、冲突提示
│  │  ├─ tool段：工具结果引用、外部证据ID、需要回查的原文指针
│  │  ├─ 形式选择：短事实高置信注入原文；长历史注入摘要+引用ID；争议记忆只注入“存在冲突”提示
│  │  └─ 超窗降级：先裁低分候选 → 只保留高层摘要 → 只保留引用ID → 请求用户确认或分步检索
│  └─ 4、可观测性日志
│     ├─ 字段：trace_id、query、recall_channels、candidate_ids、scores、graph_paths
│     ├─ 字段：selected_ids、injected_segment、token_cost、latency、filtered_reason、conflict_flags
│     └─ 样例：trace_001 | query=“用户偏好会议时间” | recall=vector:12,graph:8 | top=m102 score=0.82,m205 score=0.77 | selected=m102 | segment=user | tokens=180 | conflict=false | latency=120ms
│
├─ 七、存储Schema与治理
│  ├─ 1、节点表
│  │  └─ 字段：id、type、content、content_vector、embedding_model、created_at、updated_at、valid_from、valid_to、source、source_auth、confidence、weight、decay_rate、ttl、activation_count、last_access_at、emotion、importance、sensitivity、scope、status、version、evidence_refs、parent_summary_id、supersedes、contested_by、hash、metadata
│  ├─ 2、边表
│  │  └─ 字段：edge_id、src_id、dst_id、type、direction、weight、confidence、created_at、last_reinforced_at、decay_rate、evidence_refs、status
│  ├─ 3、日志表
│  │  └─ 写入日志、检索日志、注入日志、冲突仲裁日志、层级流转日志、审计日志分表或统一事件表
│  └─ 4、治理策略
│     ├─ 多租户隔离：scope按tenant/user/session划分
│     ├─ 隐私：sensitivity分级；敏感记忆检索和注入需策略门控与脱敏
│     ├─ 审计：深层变更、冲突仲裁、废止、人工确认全量留痕
│     └─ 备份：向量库、图库、关系库定期快照；对象存储保留原文证据
│
├─ 八、技术选型与演进路径
│  ├─ 1、浅层记忆
│  │  ├─ 默认：Redis带TTL，承载会话状态、最近轮次原文、滚动摘要草稿、工具结果临时缓存
│  │  ├─ 理由：高频低延迟、自动过期、亚毫秒读写，匹配会话生命周期
│  │  └─ 补充：需事务的会话元数据可下沉PostgreSQL；不把完整长期对话历史长期放Redis
│  ├─ 2、中层记忆
│  │  ├─ 默认组合：PostgreSQL + pgvector + Neo4j或FalkorDB
│  │  ├─ 向量默认pgvector：向量与元数据同库，支持SQL join、事务、过滤，适合每用户20万节点规模
│  │  ├─ 切Qdrant条件：向量接近/超过5000万；重度payload filtering；P99延迟瓶颈；需要原生hybrid search
│  │  ├─ 不默认Milvus：适合100M～10B+独立向量基础设施，当前规模属过度设计
│  │  ├─ 图默认Neo4j：属性图事实标准，Cypher生态和Agent集成成熟
│  │  ├─ 轻量替代FalkorDB：GraphBLAS，子10ms查询延迟，适合GraphRAG式关联召回和轻量部署
│  │  └─ 可选时序图层Graphiti：双时间窗口valid_at/invalid_at与created_at/expired_at；基于Neo4j/FalkorDB
│  ├─ 3、深层记忆
│  │  ├─ 默认：PostgreSQL版本表 + MinIO/S3对象存储
│  │  ├─ 版本表承载memory_version、deprecation_record、audit_log、人工确认记录
│  │  ├─ 对象存储保留原文和证据包，数据库只存指针和哈希
│  │  └─ 深层核心子图如需图关系，可在图库维护只读核心子图，写入权限严格受限
│  ├─ 4、记忆框架
│  │  ├─ Mem0：复用中层事实抽取、去重、ADD/UPDATE/DELETE/NOOP写管线；浅层低延迟会话和深层审计仍自建
│  │  ├─ Graphiti：复用中层时序知识图谱、双时间窗口、混合检索；简单偏好召回不必引入
│  │  ├─ Letta/MemGPT：参考Agent自管理上下文和分层记忆块；已有runtime时评估集成成本
│  │  └─ 原则：框架是加速器；参数体系和函数签名作为契约层，避免被默认语义锁死
│  └─ 5、默认栈与演进触发
│     ├─ 起步默认栈：Redis + PostgreSQL/pgvector + FalkorDB或Neo4j + PostgreSQL版本表 + MinIO/S3 + Mem0或自建精简pipeline
│     ├─ pgvector→Qdrant：向量>5000万，或过滤/延迟成瓶颈
│     ├─ FalkorDB→Neo4j：图查询复杂度和团队Cypher生态需求上升
│     ├─ 自建→Mem0/Graphiti：中层事实量级和冲突仲裁复杂度超出简单规则，或需要双时间推理
│     └─ 引入Graphiti：需要事实有效窗口和系统摄取时间的双时间推理
│
└─ 九、交付物与实施里程碑
   ├─ 1、架构总览图（文字版）
   │  ├─ 写入链路：输入解析/抽取 → 可信度评估 → 节点存储 → 即时建边 → 日志
   │  ├─ 读取链路：查询 → 多路召回 → 图游走 → 融合排序 → MMR裁剪 → 上下文注入
   │  ├─ 离线治理：衰减重算 → 压缩合并 → 层级流转 → 边剪枝 → 一致性校验 → 归档审计
   │  └─ 存储层：Redis、PostgreSQL/pgvector、图库（Neo4j/FalkorDB）、对象存储（MinIO/S3）
